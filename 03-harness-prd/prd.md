## Problem & user

RocketShip PMs need this handled: Juno consolidates and recommends prioritization of Rocketship feedback from Jira, Slack, emails and Google Drive Folders. It considers the customer providing feedback and how the feedback aligns with the company's strategy and impacts to the current roadmap.. Juno does this inside limits a human set on purpose, and defends every call it makes.

## 01 Context · Data Requirements

**Required sources, and exclusions**

- Slack threads from product issues channel
- Jira tickets automatically created from customer feedback in the system
- Emails received in the feedback@rocketship.com inbox
- Interview Transcripts in the Feedback Google Drive Folder
- Rocketship Product Strategy One-Pager
- Rocketship Product roadmap
- Sales Pipeline Snapshot

**How fresh must it be**

Juno should pull from the source data/systems on an hourly basis and ensure it is reported to the user when the last pull was. If a source is unreachable, this should also be reported within the tool to the user.

## 02 Tools · System Capabilities

**The verb list**

- Read feedback from various sources (Jira, email, slack, google drive)
- Read company documentation (Strategy, Roadmap, Sales Pipeline)
- Draft Prioritized list of feedback for human review

**Deliberate omissions**

- Juno cannot write to the product roadmap. The prioritized decisions will help inform a human to make the final say on any impacts to the roadmap and Juno should not be able to make those changes autonomously.
- Juno cannot write emails from the feedback@rocketship.com email. To prevent misinformation to customers on when the team will address the feedback by.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

Juno should pull signals from the context data sources one time every hour, if there is nothing returned Juno should inform the user that it is missing feedback from the named source.

**Latency and cost target**

Answers back in under 15 seconds almost every time, and cost per task stays predictable.

## 04 Memory · Data Requirements

**What persists, at what scope**

- Feedback is divided by product. Users are associated to one or many products. Users can only see data on the products assigned to them.
- User updates on prioritization changes persist across all users

**Expiry and write rules**

- Signals informing prioritized list persist until work associated is added to the product roadmap. Juno shall use this information to provide week over week context to feedback. Human corrections on prioritization override the modal.
- Company documentation data expires every hour or each time the modal is ran.

## 05 Permissions · AI Risks & Mitigations

**The permission tier**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | blocked |
| send | blocked |

**Justification**

- Draft list is automatic
- Read-only access to all Context sources, pull updates hourly 
- Write is blocked as Juno cannot update the roadmap, or other company documentation. If Juno were to write to the roadmap the team could shift focus incorrectly. This can be undone by the product manager but could waste valuable development time.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

The signals are all reassessed and confirmed against the consolidated summary Juno provided

**Failure behaviour**

The system should flag areas or output of concern to the user. i.e. a flag in the tool on either the consolidation of feedback into a list item or the prioritization ranking.
